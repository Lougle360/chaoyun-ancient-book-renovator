# 迭代报告与飞书云文档发布

只在用户要求复盘、保存报告或发布云文档时读取。制作古籍样张不自动触发报告或外部发布；更新Skill也不触发重发已有文档。

## 写一份能回查的迭代报告

以用户指定案例和当前实际成果为主线，核对原文件、PDF物理页／印页、各阶段PDF、校读裁决、预览图及真实反馈。原版式、古今对照、连续白话、作者口吻配图各自的V1/V2不是全书统一版本号；相邻样例和其他书的成功经验须标明来源，不能拼成该页的修改史。

报告应讲清：起点承载了什么、用户指出什么具体问题、怎样修改、修改依据是什么、成品发生了什么变化、怎样核查、还保留什么边界。优先使用实际错字、图位或语义修正，以及真实页面对照。区分机械检查、源义审查、独立模型试读与用户反馈；不虚构用户认可或真人测试。

按实际范围说明完整性：整页、选段、选图、整章分别计量。写明暂跳项；“有映射”不等于“无删节”。不要把历史仍含错图的比较页展示为现行正确底稿。

显式要求MD时保存到当前项目合适的报告目录，配套保存引用图片和来源信息。保留原报告，云发布仅生成单独的转换稿。交付前检查所有本地文件与图片引用、关键页数和最终文件绑定。页面图数量、报告篇幅和目录结构由案例决定，不照搬上一份报告的数量。

## 发布到飞书：优先已安装CLI

用户要求使用CLI时直接走CLI，不再默认扫码网页导入。未明确工具时，优先足以完成任务的已连接能力或已配置CLI。只有CLI缺少所需能力且没有可用直连工具时，才说明缺项并选其他方式。

1. **发现实际命令与身份。** 用 `command -v lark-cli` 检查PATH；若没有，再检查工作区现有入口及安装说明，例如已存在的 `./lark-cli`。不要因PATH缺失就断言未安装或重装。运行该入口的 `--help` 和 `whoami`，确认实际为用户身份。版本支持时显式选择 `--as user`；若CLI处于固定用户模式且无此flag，以当前帮助和实际身份为准。不要输出token或配置密钥。
2. **读取当前CLI技能。** 通过 `skills read lark-doc` 及对应的创建、Markdown、读取参考确认用法；只有遇到授权问题才进入认证流程。API和flag会变化，不把这里的命令例子当成永久接口定义。原样发布已完成MD适用Markdown导入，无须重新进行内容创作或转换DOCX。
3. **准备独立发布稿。** 将本地图片引用转为CLI支持的 `![说明](@./工作目录内的图片路径)`，有空格时按当前语法引用。普通本机文件链接不能成为云端下载链接：保留可理解的档案名称并说明位置性质；只有用户要求上传附件时再上传相应原文件。保存原稿哈希、转换说明、图片顺序与来源哈希。排版适配不能偷偷改正文结论。
4. **确认写入目标。** 新建请求创建新文档；用户指定修改现有文档则先读取它，走相应更新命令。用户指定文件夹／知识库时使用经工具核实的目标token；未指定时可使用当前用户文库。环境里恰好打开的网页不等于指定发布目标。已明确要求发布，不重复索取泛化确认。
5. **预检后创建。** 当前命令支持时用 `--dry-run` 核对标题、身份、目的地、资源上传计划及图片数量。长正文使用 `@./相对路径` 或stdin，避免shell转义；不要把文件正文拼入shell代码。保存实际创建结果及文档URL/ID。
6. **回读实际云文档。** 用 `docs +fetch` 读取创建后的全文及资源结构，逐项检查标题、段落、表格单元格、图注与章节；核对图片数量、顺序、资源token及可用元数据，检查warnings和未完成占位。必要时预览或下载媒体确认实际内容；布局有疑问时增加可见检查。API创建成功不能代替回读。
7. **记录并交付。** 保存发布URL、文档ID、版本号、源稿和转换稿哈希、回读结果以及验证范围；回复直接给实际返回的文档链接。内容回读证明传输完整，不新增古籍内容验收结论。不自动发送消息或扩大分享权限。

当前已验证的调用形态如下，实际执行仍以安装版本的help和技能为准；占位文件名、标题与文档ID均须替换为本次真实值：

```shell
./lark-cli docs +create --doc-format markdown --title '本次报告标题' --content '@./本次发布目录/发布稿.md' --parent-position my_library --dry-run
./lark-cli docs +create --doc-format markdown --title '本次报告标题' --content '@./本次发布目录/发布稿.md' --parent-position my_library
./lark-cli docs +fetch --doc '实际返回的文档URL' --detail full --doc-format xml
```

JSON成功信封按当前CLI约定检查 `ok: true` 和退出码；成功也要检查warnings、资源绑定及任务状态，不假定存在旧OpenAPI格式的顶层 `code: 0`。异步任务记录真实task ID并按CLI支持方式完成查询。

创建调用超时、结果不明或仅部分图片上传成功时，先查已保存URL、文档ID、任务ID和实际云内容，再决定补传或更新。不要盲目重复create造成多份报告。缺少必要权限时保存本地发布稿和已完成状态，按CLI的最小范围授权提示处理；不能靠切换身份或反复重建掩盖权限问题。

本项目《三白宝海》报告的实测结果为：用户身份创建云文档，六张本地PNG自动上传并绑定，回读六张图片、六个表格及239个文本检查单元。它证明这条CLI路线可用；后续报告必须按自身内容重新计算与检查，不套用这些数量，也不沿用旧文档ID。
