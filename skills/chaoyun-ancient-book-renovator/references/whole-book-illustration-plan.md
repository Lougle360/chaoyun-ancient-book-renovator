# 整书分析与配图方案

适用于新建或继续批量制作的整书普通读者版。独立选页样张沿用 [样张流程](illustrated-reader-samples.md)，不需要虚构整书方案。方案是编辑工作的内部交付，读者正文仍按选定风格呈现。

## 在流程中的位置

**原图清点与校读 → 全书理解 → 阅读设计及整书配图方案 → 阅读单元确认 → 代表样章与样图验证 → 批量转写、绘图与排版。**

- 诊断和原貌重建阶段负责清点原图、子图、图中文字、所在物理页／印页与源块，确认图文归属和未决项。
- `book_understood` 阶段分析全书实际讲什么、各章如何联系、读者要理解哪些形态、数量、空间或论述关系。依据可靠源文和原图，不凭书名选择整套画风。
- `reader_designed` 阶段由今读编辑主责，结合原貌重建和古文今译的判断，完成必备文件 `50-edited/illustration-plan.md`。它从 `book-understanding.md` 接收内容依据，和 `editorial-plan.md` 相互引用。
- 含固定原文、符箓或难字时，按[文字／图像处理规范](text-image-and-rare-glyph-policy.md)接收原貌重建已登记的保护范围，在方案中明确正文、原咒、旁白、图内构形字迹和普通标签的去向；图与咒的配用关系、操作次序及缺失／未定关系都要有源依据。保护原字的决定必须早于繁简转换，不能等到配图阶段才撤回误改。
- 代表图在样章阶段验证，并写入必备文件 `50-edited/sample/illustration-review.md`。复用已有样章和实际独立审读，不另造第二套同义试验。
- 配图检查是现有设计与样章关卡的一部分，不新增阶段名称，不跳过 workflow 1.10 的阅读单元、忠实性和出版要求。

## 配图方案必须回答的六件事

| 项目 | 需要作出的具体决定 |
|---|---|
| 全书特点与读者需要 | 主要内容、章节关系、图像承担的解释任务；混合型书按章节分别判断 |
| 原图处理 | 每一内容图及子图保留、重绘、拆解、合并或暂待核的去向；有据地解释重复图复用与例外 |
| 新增图依据 | 哪段文字存在实际理解障碍，新增图解释什么，源文依据是什么；艺术情境和源事实分别记录 |
| 制作路线 | 自然景物用生成插图，点阵、数字、卦爻、方位、普通标签用精确绘制；构形字迹保原形，原咒另排正文；混合图说明两者怎样组合 |
| 全书视觉规范 | 绘画质感、视角、文字层级、色彩含义、方向约定、符号、图注与比较方式；规范可因书而异 |
| 代表图与检查办法 | 优先试制哪些不同图型、困难和高风险关系；怎样证明读者看懂、源义保持、精确信息正确 |

正文可用连续说明，配图清单可用表格或链接已有结构化图像清单，不强制重复建账。每个拟交付图项至少能回查：

- 稳定 `figure_id`，来源页、源块及需要时的子图位置；新增图也有支持它的文字来源。
- 所属章／阅读单元、读者应看懂的要点、处理方式、制作路线。
- 不能改变的关键关系，例如山脉连接、水路来去、数位、方向、卦爻；可自由设计的表现部分。
- 计划放置位置、可复用素材、未决问题ID、是否纳入代表图试制及理由。

每章说明配图需求或无需新增图的理由。全书没有需要插图的内容时，方案记录这一判断及所检查的源范围，样图审核记录其复核结果即可；不制造装饰图满足数量。原书已有内容图不能用“无需新增”掩盖漏图。页数、图数和试制图数由内容决定。

## 设计检查与批量前检查

`reader_designed` 标为通过前，确认全书范围已分析、原图及子图均有去向、每项制作选择有用途和来源、代表图覆盖真实难点。尚待试制的图保持计划状态，不能预填“已通过”。中央图义或全书方法尚未明确时，先解决或明确缩小授权范围。

在实际样章页面中试制代表图，检查图形与正文一起阅读的效果。山形图检查轮廓、体积和结构差异；数量图检查数目与位置；混合图同时检查标签和景物对应。需要精确的信息从实际PDF核对。独立读者先作真实理解回答，再与原图及校读证据比较，沿用 [实际读者会话](reader-production.md) 的独立性要求。

`illustration-review.md` 记录：计划版本／哈希、试制图ID、实际样章PDF和素材／预览引用、审核执行与模型或真人类型、逐项发现、修改和复查结果、尚未覆盖的图型及后续处理。可以引用同一次读者会话的原始记录，不能只复制一句“样章通过”。无图方案记录实际复核依据，不要求虚构图像或题目。

只有方案完成且代表图的实质问题解决，才按已验证方法批量生产。未验证的新图型在首次批量使用前补小范围试制；不要求已经通过且输入未变的图重复从零审核。整书新发现、意义修正、关键结构或视觉语义变化时，更新方案，保留旧稿，复核受影响范围。

## 生产计划绑定与校验

新整书任务的 `50-edited/production-plan.json` 使用 `schema_version: "1.1"`，保留已有字段及要求，在 `bindings` 中加入：

- `50-edited/illustration-plan.md` 的实际SHA-256；
- `50-edited/sample/illustration-review.md` 的实际SHA-256；
- 方案／审核引用的实际图像清单、样图、样章PDF或预览等本地证据，按本次使用范围绑定。

批量前运行 `python scripts/validate_production_plan.py WORKSPACE`。schema 1.1校验要求上述两个文件存在、非空、位于工作区内且哈希一致；既有校验继续核对来源、样章、读者会话和阅读单元。该脚本不判断计划写得好不好、图是否齐全或读者是否真的理解，内容检查由上述实际审核完成。最终出版仍须逐幅核对成品与方案及有记录的变更。

历史production-plan schema 1.0继续支持原合同检查，但不代表通过本新增环节。采用更新后方法继续整书批量工作时，补齐真实方案与审核后升级为1.1；不得只换版本号或补模板文本。保留旧成品及审核，不在Skill更新时重新发布或覆盖书稿。
