# 原字保形、残形与缺损兜底

适用于难字、咒音或符号经过实际核查仍不能确定的材料，以及原字裁片嵌排后的验收。先按[文字与图像处理规范](text-image-and-rare-glyph-policy.md)决定哪些文字需要保留原文；本规范补充无法释读时的交付方法，不改变 workflow 1.10、现有 schema、疑点生命周期或正式出版等级。

## 先分清形、字、音、义

分别记录可见形状、标准字符身份、读音、语义的证据和状态。保存了形状，不等于认出了字符；认出字符，不等于确认其咒音；读音确定，也不自动解释整句。若字符已经可靠确认、只有读音未定，正文保留该字符，不必退回图片。

依次检查原始扫描及上下文、同书复现、更清晰的同版或有出处的异本、可靠字书；按实际需要选择，并记录真正查看过的页和范围。网上转录只作线索。异本须核对版本与上下文，作为独立见证保留，不拼成混合咒句。没有访问到的资料、没有发生的专家复核不能写成已完成；检索无结果时停止猜补，保存现有证据。

| 源证据状态 | 正文处理 | 保留的限制 |
|---|---|---|
| 字符身份可靠，仅字体不覆盖 | 换覆盖字体并嵌入，核对实际渲染与复制 | 字体修复不改变原字或读音状态 |
| 字形清楚，但不能唯一映射字符 | 将真实源字按正文次序嵌排；可使用经过核验的字模 | 标明未释，不赋猜测的 Unicode、拼音或读法 |
| 字已残损，仍留有可辨的笔画片段 | 保存真实残形并嵌排，明确它是残形 | 不补笔，不把短残片拉伸成完整字，不声称恢复全字 |
| 确认只有一个字位，但没有可用的字形证据 | 用 □，保留对应源区 | □ 是编校占位，不是原字，也不提供读音 |
| 连续损缺，字数不能确定 | 用〔缺损〕并保留整段源区 | 不压缩成一个字位，不按常见咒式猜长度 |
| 连笔、符字或相邻笔画无法可靠分割 | 保留足够的原图关系或局部源片 | 不强拆字符，不把邻字笔画冒充该字 |

已知多字位缺失按实际可证的数量记录；不能把“多个”写成“一字”。未定读音不根据偏旁、语境、常见咒式或普通话习惯补出。确需提供经字书验证的现代字音时，明确它只是该字的现代读音，不能称为该咒的传承读法或据此合成确定的咒音。

核查范围包括已转录成普通汉字的部分，不能只查 □ 和低置信度项。有新证据否定旧映射时，保留旧记录、退回真实字形，并沿用或关联原疑点 ID。

## 制作源字与残形资产

保留不可变的原扫描。从原像素裁取，记录源图尺寸、页码／源块、坐标单位与边界约定；使用确定的裁切方法。不得把生成式补笔、涂抹、阈值清理后的图当作原字证据。改善显示可另建有处理说明的派生图，但原始裁片始终保留，字形信息须能逐项核回。

先看整页与相邻字，再检查裁片：是否裁断笔画、带入邻字或边框、误把污迹认成笔画。不能可靠分割时保留更大的源区并说明，不能为了整齐强行割出一个字。普通可识别文字仍排为正文，不把整段咒文图片化来绕过难字。

使用稳定字形 ID（例如 G001）与既有统一疑点账本关联。字形映射至少能回查：

- 源文件／页图及其哈希、物理页与源块、原图尺寸、裁切坐标及约定。
- 裁片路径、文件哈希、像素哈希；清楚原形、残形、不可分割源区等分类。
- 成稿出现位置与顺序、采用的字符映射（允许为空）、字音与字义的已知／未定状态及依据。
- 正文显示方式、复制回退文字、关联的 candidate／issue ID。保留整段源证据，不能只剩孤立小字。

该映射是字形资产的补充证据，不是另一套疑点账本，也不替换现有 block ID 或 reader-unit kind。坐标、字符与 hash 应从真实文件取得；不得用自填“通过”字段代替检查。

## 嵌排与复制必须分别验证

同一区域沿用统一字号和基线，为原字／残形分配一致的字位，保持源形宽高比。残形按其原有尺度和相对位置显示，不能为了填满字位拉长或补成完整字。检查行首、行尾、换行和上下文，避免字形漂浮、挤字、截笔或误连。

Markdown 用实际引用的字形资产，并写出不冒充原字的 alt／回退文字，例如 `〔原字G001：未释〕` 或 `〔残形G014：未释〕`。普通文字保持正常文本。PDF 可用 `ActualText` 等机制承载同一回退；不能暗藏猜字来追求“可搜索”。若目标阅读器不能稳定复制，交付对应纯文本回退文件并明示限制，不能宣称 PDF 已无损复制。

**实际遇到的陷阱：** ReportLab 的 `Paragraph` 在本案例中先绘制内联图片、后绘制正文；即使画面位置正确、每个字形都有 `ActualText`，提取时回退标记仍会堆到句首。应保证文字片段与字形按阅读顺序写入，或采用经验证可保持次序的渲染方式。该问题不能靠添加 ID 或检查字形数量解决；不限定所有项目使用同一个渲染器。

| 检查对象 | 应核实的内容 |
|---|---|
| 源字资产 | 裁片像素与声明的原图区域一致；全字／残形分类正确，附近笔画未被混入 |
| 实际 PDF | 嵌入的字形仍与所用资产一致，字位、基线、宽高比和相邻文字正确；字体实际嵌入 |
| 复制与提取 | 对照含前后文字的完整序列，核字形的先后、重复次数和跨行关系；至少一次使用独立于渲染器的实际 PDF 提取或复制 |
| Markdown 与回退文件 | 字形引用可解析，顺序和回退值与 PDF 对应；不以另一个文件正确替代 PDF 的检查 |
| 读者说明 | 读者知道哪些是原字、残形及缺损标记，并知道保形不等于能够念出全部咒音 |

提取不一致时再用其他阅读器／提取器定位差异。工具只能检查它实际覆盖的内容；逐页实看、原文字序和含义仍需审读。现有流程若不能解析所选内联表示，先适配并验证有明确映射的读取方式；不得删除字形、剥掉任意标签或放宽出版校验来制造通过。有限范围的试读交付须如实登记其限制。

## 分开记录两种结论与用户验收

1. **原文与原形保存：** 核对可识别文字、真实原字／残形、字序、重复、源区及缺损边界是否完整忠实。
2. **咒音能否完整还原：** 核对是否每个诵读位置都有可靠读音依据。仍有未释字、未知音或无法判断的缺段时，明确“尚不能完整还原咒音”。第一项通过不自动推出第二项通过。

未定音义继续留在统一账本。修好字体、嵌排或复制只完成相应显示问题，不把文字问题关闭，不把严重程度改低来凑正式出版等级。普通理解是否受影响与逐字诵读是否可恢复，可以得出不同结论。

用户确认某版本合格时，按对话中实际约定的范围登记验收：保留原话、记录时间、版本、成稿／PDF 路径与哈希、已披露的限制、技术审核证据；不自行缩小或扩大用户的确认。追加验收事件，并同步项目当前状态与索引，冻结已验收文件。用户接受带明示残缺的版本，不等于这些残缺被释清，也不自动把试读版本改成正式出版、将所有阶段改为通过或关闭未决项。后续改动形成新候选，并按影响范围重新审读、渲染和绑定证据。

《秘诀仙机》V10 验证了这一兜底：真实原字和残形进入正文、未知长度缺损明示、复制回退按字序读回，用户接受该检查点；它没有恢复所有咒音。该案例是方法依据，不是其他书现成的验收证据，不能把其字形数量、页数或结论写成通用模板值。
